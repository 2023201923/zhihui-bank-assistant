# 智汇银行智能客户经理

零售银行对话式服务演示。文档日期：2026-11-01。内容以当前代码为准。

---

## 1. 系统定位

客户在微信小程序中用口语办理业务。系统识别需求后查询账户，并生成业务卡片。资金类业务在客户核对确认卡、输入交易密码后入账。

业务范围共八类：转账、账单、银行卡、订阅代扣、风险测评与理财、心愿备用金、适老服务、亲情反诈。

大模型负责识别客户需求、选择调用哪项功能、填写参数，并把结果组织成文字。金额、余额、限额、卡片状态、风险等级和赎回日由程序计算。模型不能改写这些结果。

客户、卡片、流水和业务记录保存在本机数据库。本系统未连接核心系统、支付通道和短信网关。

## 2. 业务范围

登录后首页提供八个入口。客户也可以直接输入文字。

### 2.1 智能转账

客户提供收款储蓄卡卡号和金额后，系统生成转账确认单。收款人是本行客户时，确认单同时显示户名和卡号，并列出本笔转出后的剩余额度。

| 客户提供的信息 | 处理结果 |
| --- | --- |
| 只有姓名或手机号 | 继续要求提供收款储蓄卡卡号 |
| 本行储蓄卡卡号和金额 | 生成确认单。密码校验通过后，资金实时记入对方活期账户 |
| 本行信用卡 | 拒绝，并要求更换储蓄卡 |
| 本人名下卡片 | 拒绝 |
| 卡号格式正确，但不是本行账户 | 扣减付款人可用余额，并记一笔流水 |

信用卡不用于转账，也不用于理财申购。付款卡须为状态正常的储蓄卡。冻结、挂失或其他非正常状态的卡片，在生成确认单之前被拒绝。

限额按付款卡统计。校验顺序为：卡片是否存在且为储蓄卡、卡片状态、金额是否大于 0、单笔限额、单日笔数、单日金额、年度金额、活期余额。任一项未通过，不生成可确认订单，并说明原因；额度不足时给出调额引导。调整限额须输入交易密码。客户可调整的上限为：单笔 50 万元、单日 100 万元、单日 100 笔、年度 5,000 万元。确认环节再次执行同一套限额校验。

限额校验通过后，再按第 4 节识别转账风险。风险提示不替代限额校验。超限交易不进入确认。

### 2.2 账单分析

客户可查询账单和消费结构，也可询问支出是否偏高、支出结构如何。查询账单时返回账单卡片。分析支出时，系统先读取真实分类和流水，再以文字说明。

客户只说月份、未说年份时：本月和已经过去的月份按当年统计，尚未到来的月份按上一年统计。客户明确说明今年、去年或某一年时，按该年统计。

### 2.3 银行卡

客户可查看储蓄卡、信用卡、卡片状态，以及单笔、单日金额、单日笔数、年度四项限额。挂失、冻结、解冻和调额须先指明卡片，再生成确认卡。挂失、冻结、解冻在卡片上确认。调整限额须输入交易密码。

### 2.4 订阅代扣

客户可查看已开通的免密代扣和自动续费，并按商户名称退订。退订先生成确认卡。客户确认后，订阅状态变更为已取消。

推荐按以下顺序处理：

1. 个性化推荐和申购须有一年内的有效测评。问卷共 11 题，并选择职业。得分对应 R1 保守型、R2 谨慎型、R3 稳健型、R4 进取型、R5 激进型。测评日由服务端写入，有效期 365 天。
2. 风险等级向客户确认，不要求重新作答。用钱时间由客户说明，选项为：随时要用、一周内不用、一个月内不用、半年内不用、一年以上不用。
3. 候选产品先排除高于客户风险等级的产品，再按用钱时间收敛期限。客户已经说明用钱时间时，按客户说明处理，不以流水推断覆盖。
4. 排序使用近 90 天流水、可投闲钱、年龄、职业和已持产品。可投闲钱按可用余额扣除约 3 个月开支计算。推荐在不同期限上分散。已持有的产品降低排序，并标明持仓金额。
5. 方案说明分三段：筛选依据、具体安排、请客户确认是否合适。客户可改为更灵活的期限、更长的期限、重新确认用钱时间，或重新测评。

理财画像汇总风险类型与等级、测评是否在有效期内、月均支出、可投闲钱、活期余额、持仓，以及「活钱管理 / 稳健增值 / 长期增值」三项建议比例。未测评时不给出配置比例。申购金额达到起购金额并选定付款储蓄卡后，生成申购确认单。密码校验通过后扣款，并记入理财流水。

### 2.6 心愿备用金

客户将一笔活期资金单独保留到指定日期使用。用途包括送礼、购物、旅行和一般备用。资金从活期划出，不另选银行卡。客户未说明受益人时，不填写受益人，也不追问。

用途、金额和用钱日均出现在客户原话中时，生成确认单。金额须带货币单位，包括「元」「块」「千」或「k」。用钱日支持「11月5号」「下个月5号」「下周三」等说法，且须晚于当天。缺少任何一项时，只追问所缺项，不生成确认单。

密码校验通过后，可用余额减少，锁定资金增加。底层产品固定为在售 R1 产品「智汇·活钱」。参考年化按交易日计提，周末和法定假日顺延至下一交易日。15:00 前确认的，下一交易日开始计息；15:00 及以后确认的，再顺延一个交易日。演示环境计算收益，不承诺、不保本。

赎回日按以下规则计算：用钱日为周末或法定假日时，先对齐到前一个工作日，再往前 3 个工作日。若由此得到的赎回日晚于用钱日前可到账的日期，系统告知该日期过近、资金不能在用钱日前回到可用余额，请客户改期，同时不生成确认单。当日确认的心愿备用金，当日不自动赎回。

客户可查询存续中的记录和已完成的历史。列表按用钱日排序，同一天再按创建时间排序。客户说明取回第几笔时，按该顺序办理。取回同样须确认并输入交易密码，本息立即回到可用余额。赎回日当天，调度任务将本息划回可用余额；客户打开小程序时看到提示。用钱日当天若已经赎回完成，再提示一次可以按计划使用。提示在小程序内展示。演示环境不发送微信模板消息，也不发送运营商短信。

### 2.7 适老服务与语音

年龄段为 51–60 岁、60 岁以上、61–65 岁或 65 岁以上的客户，首次登录进入适老版。客户可在顶部切换适老版与普通版。选择保存在本机，之后以客户选择为准。

适老版放大正文、金额、按钮和理财信息。理财卡片优先展示收益率、期限、起购金额和风险等级，长篇说明折叠。开启语音后，助手回复自动朗读，单条消息可再次朗读。语音优先使用中文女声。网络语音当次不可用时，改用本机系统语音。下一句仍先尝试网络语音。

### 2.8 亲情反诈

客户可查看安全防护，并绑定紧急联系人。关系选项为子女、父母、配偶、亲属、其他，同时登记姓名和手机号。演示客户高苏尧已绑定女儿周可，手机号 13800004466。

转账被评为高风险时，系统生成预警原文，展示在确认单上，并写入预警记录。已绑定紧急联系人时，确认单显示已通知家人及通知原文。未绑定时，提供绑定入口。演示环境将通知原文展示给操作者，不向运营商投递短信。高风险目前对应第 4 节的连续大额。其余风险信号为一般提醒，不触发亲情预警。

## 3. 控制原则

| 原则 | 规则 |
| --- | --- |
| 理解与判定分开 | 模型选择功能并填写参数。金额、余额、限额、卡状态、风险等级、赎回日由程序计算，并按程序结果展示。 |
| 确认后入账 | 转账、理财申购、调整限额、退订代扣、心愿备用金存入和取回，均先生成确认卡。客户在卡片上核对并输入 6 位交易密码后，余额和业务记录发生变更。 |
| 文字回复不完成办理 | 客户回复「是」「是的」「对」「好」「好的」「可以」「行」「确认」「确定」「没问题」「嗯」或「ok」时，若上一张确认卡仍待处理，系统将该卡重新展示在对话底部，并提示在卡片上输入交易密码。文字回复不扣款。 |
| 未执行时如实说明 | 本轮没有确认卡时，回复不得写已经转账、已经预留、已经冻结、已经挂失或已经生成确认单。系统将这类表述改写为「这一步尚未执行」。 |
| 要素取自客户原话 | 收款卡号、金额、用途和用钱日以客户原话为准。程序不补默认金额，不补默认日期，不把提示词示例中的人名、商户或卡号写入单据。 |
| 销售适当性 | 一年内没有有效风险测评时，理财画像可以查看，页面标明「未测评」，且不给出配置比例。了解产品、索取建议、查看详情和申购，均先进入风险问卷。产品风险等级高于客户等级时，不予销售。 |
| 收益表述 | 回复和卡片均不承诺保本、不承诺保收益。业绩比较基准、投资范围和风险揭示随产品展示。 |

交易密码只在确认卡上输入。对话过程中不向客户索取密码。

## 4. 转账风险识别

生成确认单时，系统依据付款人本人的转账流水识别风险。模型不参与这项判断。

| 信号 | 条件 | 处理 |
| --- | --- | --- |
| 连续大额 | 本笔不低于 2,000 元，且近 72 小时内已有不低于 2,000 元的转出 | 高风险。提交前须勾选已知晓。已绑定紧急联系人时生成亲情预警 |
| 单笔大额 | 本笔不低于 5,000 元，且未构成连续大额 | 提醒核对收款人。提交前须勾选已知晓 |
| 首次大额收款人 | 本笔不低于 2,000 元，且近期转账记录中没有该收款人 | 提醒勿向无法核实身份的账户汇款 |
| 当日高频 | 本笔不低于 2,000 元，且当日转账笔数已达 5 笔 | 提醒确认为本人主动发起 |
| 夜间大额 | 本笔不低于 2,000 元，且发生在 0:00–6:00 | 提醒在夜间再次核实收款人 |
| 整数大额 | 金额不低于 10,000 元，且为 1,000 的整数倍 | 提醒确认用途真实 |
| 快进快出 | 本笔不低于 2,000 元，且近 24 小时内有资金转入 | 提醒确认资金来源与用途 |
| 临近限额 | 本笔转出后，日累计或年度累计已用额度达到上限的 80% 及以上 | 在确认单上提示剩余额度 |

风险等级为高风险或一般提醒时，客户须勾选已知晓，再提交交易密码。临近限额属于额度提示，与上述风险勾选分开展示。

## 5. 对话处理流程

每句客户消息按以下顺序处理。前一步已经确定返回内容时，不再执行后续步骤。

1. 将客户原话写入该客户的会话。发给模型的上下文保留最近 10 轮。服务端会话最多保留最近 20 条。
2. 若上一张办理确认卡仍为待确认，且本句只是肯定回复，将该卡重新发到底部，并提示在卡片上输入交易密码。
3. 当前对话被判定为购买商品、且没有理财含义时，本轮移除理财货架、产品详情、配置建议和申购。系统说明不提供商品导购。客户要求把资金单独留到某一天时，进入心愿备用金。
4. 主模型自行决定调用哪项功能，最多 5 步。某一步已经生成卡片后停止，不再让模型把卡片复述成文字。
5. 本句是取消、取回或提前取出心愿备用金时，以取回结果替换模型回复。客户说明第几笔时，按列表顺序取该笔，第一笔为 1。多笔但未说明第几笔时，按列表顺序追问。
6. 本句同时具备心愿备用金意图、带单位的金额、可解析的用钱日和用途，且第 4 步没有卡片时，直接生成存入确认卡。任一项缺失，则不在此补卡。
7. 第 4 步已有卡片，且第 5、6 步未接管时，返回最后一张卡片。
8. 主模型只有文字时，启动一致性检查。检查优先使用 `Qwen/Qwen3.5-35B-A3B`，调用失败时改用主模型。两边均无法调用，或返回内容不是合法结果时，保留主模型原文。
9. 检查判定客户要求查看账单、银行卡、订阅、安全中心、理财画像、理财货架、产品详情、风险问卷或心愿列表，而回复中没有卡片时，补调对应的查看功能并返回卡片。检查不生成转账、申购、存入、取回、冻结或退订确认单。
10. 前面已经说明用途和金额，本句能够解析为今天之后的用钱日时，补一张心愿备用金确认卡。用钱日按客户原话换算。
11. 最近对话为转账，金额和收款储蓄卡卡号均已出现在客户原话中时，补一张转账确认卡。只有姓名、没有卡号时，改为追问储蓄卡卡号。
12. 检查判定文字声称已经办理、但本轮没有确认卡时，返回改写后的一句说明。其余情况返回主模型原文。主模型没有文字时，返回一句可办理业务的提示。

主模型为通义千问 `Qwen/Qwen3.5-122B-A10B`，通过魔搭推理接口调用。长思考关闭，功能由模型自行选择。

密码确认使用单独接口。成功回执写入该客户会话，响应中带最新余额，小程序据此刷新顶部余额。

## 8. 演示环境

运行环境为 Windows、Python 3.10 及以上，以及微信开发者工具。模型令牌配置在环境变量 `MODELSCOPE_TOKEN` 中。

```powershell
cd "Bank agent"
python -m pip install -r requirements.txt
$env:MODELSCOPE_TOKEN = "魔搭推理令牌"
python init_db.py
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8001
```

然后用微信开发者工具打开 `BankingMiniprogram`。本地设置中关闭合法域名校验后，小程序可以访问 `http://127.0.0.1:8001`。仓库中的本地配置已关闭该校验。先启动服务，再编译小程序。接口说明页为 `http://127.0.0.1:8001/docs`。

语音播报优先使用微软晓晓，本机须能访问语音服务。当次访问失败时，改用 Windows 系统语音。网络语音语速用环境变量 `TTS_EDGE_RATE` 调整，系统语音语速用 `TTS_RATE` 调整。

## 9. 系统边界

- 账本、限额和流水保存在本机数据库，用于演示上述控制规则。
- 跨行转账扣减付款人可用余额并记录流水，不对外支付。
- 亲情预警将通知原文写入预警记录，并展示在确认单上。
- 心愿备用金的计息、工作日和到点赎回在本服务内完成。产品与收益率为演示数据。
- 重启服务后，当前对话和尚未入账的确认卡清空。已经确认的转账、申购和心愿备用金保留在数据库中。
- 模型通过外部推理接口调用。正式部署时，可将同一套功能与规则接入行内模型。
