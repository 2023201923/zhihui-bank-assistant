# 智汇银行智能客户经理

零售银行对话演示。文档日期：2026-11-01。按当前代码编写。

---

## 1. 系统定位

客户在微信小程序里用口语办业务。系统听懂之后查账户、出卡片。客户在卡片上核对，并输入交易密码，钱才入账。

能办八类业务：转账、账单、银行卡、订阅代扣、风险测评与理财、心愿备用金、适老服务、亲情反诈。

金额、限额、风险等级、卡片状态由程序判定。大模型负责听懂客户要什么、调用哪项功能、把结果说清楚。

数据在本机。演示客户也在本机。未连接核心系统、支付通道和短信网关。

## 2. 控制原则

模型负责理解。金额和风控由程序判定。

| 原则 | 做法 |
| --- | --- |
| 理解与判定分开 | 模型选择功能并填写参数。金额、余额、限额、卡状态、风险等级、赎回日由程序计算。 |
| 先确认，后入账 | 转账、理财申购、调额、退订代扣、心愿备用金存入和取回，都先出确认卡。客户核对并输入 6 位交易密码后，余额和业务记录才变。 |
| 口头同意不算办完 | 客户回复「是」「确认」「好的」时，确认卡重新出现在底部，并提示到卡片上操作。聊天文字不扣款。 |
| 没办成就照实说 | 没有确认卡时，回复里不能说已经转账、已预留、已冻结或已生成确认单。系统会改掉这种说法。 |
| 要素用客户原话 | 卡号、金额、用途、用钱日以客户说过的为准。程序不补默认金额和默认日期，也不把示例里的人名、商户、卡号写进单据。 |
| 适当销售 | 一年内没有有效风险测评时，理财画像可以看，页面写「未测评」。看产品、要建议、看详情、申购，都先做风险问卷。产品风险高于客户等级时不能买。 |
| 收益说法 | 回复和卡片都不承诺保本、保收益。业绩比较基准、投资范围、风险揭示随产品展示。 |

交易密码只在确认卡上输入。对话里不向客户要密码。

## 3. 可办业务

登录后首页有八个入口，也可以直接打字。

### 3.1 智能转账

客户说出收款储蓄卡卡号和金额后，系统出转账确认单。本行客户会同时显示户名和卡号，并列出这笔转出后还剩多少额度。

| 客户给的信息 | 结果 |
| --- | --- |
| 只有姓名或手机号 | 继续要储蓄卡卡号 |
| 本行储蓄卡卡号和金额 | 出确认单。密码通过后，钱实时进对方活期 |
| 本行信用卡 | 拒绝，要求换储蓄卡 |
| 本人的卡 | 拒绝 |
| 卡号格式对，但不是本行账户 | 扣付款人余额，记一笔流水 |

信用卡不能转账，也不能买理财。付款卡必须是正常的储蓄卡。冻结、挂失的卡在出确认单前就被拦住。

限额按付款卡计算，顺序是：卡状态、单笔、单日笔数、单日金额、年度金额、活期余额、转账风险。有一项不过，就不出确认单，并说明原因。额度不够时给出调额引导。调额也要交易密码。客户自己能调到的上限：单笔 50 万元，单日 100 万元，单日 100 笔，年度 5,000 万元。确认时再查一遍限额。

### 3.2 账单分析

客户可以看账单和消费结构，也可以问「花得是不是偏多」「帮我讲讲支出」。看账单时出账单卡。做分析时，先读真实分类和流水，再用文字说明。

只说「几月」、没说年份：这个月和已经过去的月份按今年算，还没到的月份按去年算。说了今年、去年或某一年，就按那一年算。

### 3.3 银行卡

可以看储蓄卡、信用卡、卡状态，以及单笔、单日金额、单日笔数、年度限额。挂失、冻结、解冻、调额要先指明是哪张卡，然后出确认卡。挂失、冻结、解冻在卡片上确认。调额要输入交易密码。

### 3.4 订阅代扣

可以看已开通的免密代扣和自动续费，并按商户名退订。退订先出确认卡，确认后才改状态。

### 3.5 理财

在售 9 款，按「多久不用」和「能不能接受波动」排列。名字是「智汇·期限·取向」。下表收益率是演示用的参考年化，不保证收益。

| 智汇·活钱 | R1 | 随时取用，T+0 | 1.98% | 0.01 元 |
| 智汇·七日·稳健 | R1 | 7 天 | 2.23% | 100 元 |
| 智汇·七日·进取 | R2 | 7 天 | 2.98% | 1 元 |
| 智汇·月度·稳健 | R1 | 30 天 | 2.38% | 1,000 元 |
| 智汇·月度·进取 | R2 | 30 天 | 3.24% | 0.01 元 |
| 智汇·半年·稳健 | R2 | 180 天 | 3.45% | 1,000 元 |
| 智汇·半年·进取 | R3 | 180 天 | 3.85% | 1,000 元 |
| 智汇·年度·稳健 | R3 | 360 天 | 4.12% | 10,000 元 |
| 智汇·年度·进取 | R4 | 360 天 | 5.20% | 10,000 元 |

购买按产品编号或完整名称匹配。只说「智汇·月度」、对应多款产品时，系统列出可选产品和起购金额，不自己挑一款。

推荐步骤：

1. 一年内要有有效测评。问卷 11 题，另选职业，结果对应 R1–R5。测评日由服务端写入，有效期 365 天。
2. 风险等级只向客户确认。用钱时间要客户自己说：随时要用、一周内不用、一个月内不用、半年内不用、一年以上不用。
3. 先去掉超过客户风险等级的产品，再按用钱时间筛期限。客户已经说了用钱时间，就按客户说的办。
4. 再看近 90 天流水、可投闲钱（先留出约 3 个月开支）、年龄、职业和已持产品。不同期限都会安排到。已经持有的产品靠后，并标出持仓。
5. 方案分三段：为什么这样筛、怎么安排、请客户看是否合适。客户可以改成更灵活、期限更长、换一种用钱时间，或重新测评。

理财画像包括：风险类型和等级、测评是否有效、月均支出、可投闲钱、活期余额、持仓，以及「活钱管理 / 稳健增值 / 长期增值」的建议比例。未测评时不给比例。金额达到起购、并选定付款储蓄卡后，出申购确认单。密码通过后扣款，记入理财流水。

### 3.6 心愿备用金

客户把一笔活期单独留到某一天用。送礼、购物、旅行、备用都可以。钱从活期划出，不用选卡。客户没说受益人，就不填、也不问。

用途、金额、用钱日都在客户原话里时，出确认单。金额要带单位，如「元」「块」「千」。用钱日可以是「11月5号」「下个月5号」「下周三」，而且要晚于今天。缺哪项就只问哪项。

密码通过后，可用余额减少，锁定资金增加。底层产品是 R1「智汇·活钱」。按参考年化在交易日计息，周末和法定假日顺延到下一交易日。15:00 前确认，下一交易日开始计息；15:00 及以后再延一个交易日。演示里会算出收益，不承诺、不保本。

赎回日：用钱日遇到周末或法定假日，先对齐到前一个工作日，再往前 3 个工作日。这样排出的赎回日如果晚于用钱日前能到账的日期，就告诉客户这个日子太近，请改晚一点，同时不出确认单。当天存入的，当天不会自动赎回。

可以看还在存的，也可以看已经完成的。按用钱日排序，同一天再按存入时间。说「取回第几笔」就按这个顺序办。取回也要确认和交易密码，本息马上回到可用余额。赎回日当天，钱划回可用余额，客户打开小程序时能看到提示。用钱日当天如果已经赎回，再提示一次可以按计划使用。提示只在小程序里。演示不发微信模板消息，也不发运营商短信。

### 3.7 适老服务与语音

年龄在 51–60 岁、60 岁以上、61–65 岁或 65 岁以上的客户，第一次登录进入适老版。顶部可以随时切换适老版和普通版，选择记在本机。

适老版把正文、金额、按钮和理财信息放大。理财卡优先显示收益率、期限、起购金额和风险等级，长说明收起来。可以开语音，助手的回复会自动念，单条消息也可以再念一次。优先用中文女声。网络语音不可用时，这一次改用本机语音。

### 3.8 亲情反诈

客户可以看安全防护，并绑定紧急联系人的关系、姓名和手机号。高苏尧已绑定女儿周可，13800004466。

转账被评为高风险时，确认单上显示预警原文，并写入预警记录。已经绑定家人时，确认单写明已通知家人。还没绑定时，给出绑定入口。演示只在确认单上展示这段通知，不发给运营商。

## 4. 转账风险识别

出确认单时，按付款人自己的转账流水判断。模型不参与这项判断。

| 信号 | 条件 | 处理 |
| --- | --- | --- |
| 连续大额 | 本笔不低于 2,000 元，且近 72 小时已有不低于 2,000 元的转出 | 高风险。确认前勾选已知晓。已绑定家人时生成亲情预警 |
| 单笔大额 | 本笔不低于 5,000 元 | 提醒核对收款人，确认前勾选已知晓 |
| 首次大额收款人 | 本笔不低于 2,000 元，且近期转账里没有这个收款人 | 提醒不要转给核实不了的账户 |
| 当日高频 | 本笔不低于 2,000 元，且当天已经转了 5 笔 | 提醒确认是本人主动转的 |
| 夜间大额 | 本笔不低于 2,000 元，且在 0:00–6:00 | 提醒夜间再核实收款人 |
| 整数大额 | 不低于 10,000 元，且是 1,000 的整数倍 | 提醒确认用途是真的 |
| 快进快出 | 本笔不低于 2,000 元，且近 24 小时有钱转入 | 提醒确认资金来源和用途 |
| 临近限额 | 转出后剩余额度低于限额的 20% | 确认单上提示剩余额度 |

高风险和一般提醒都要先勾选已知晓，才能提交密码。超限的交易进不了确认。

## 5. 对话处理流程

```
客户说话
    │
    ├─ 上一张确认卡还没处理，客户只回复「是 / 确认 / 好的」
    │     → 把这张卡再发到底部，提示输入交易密码
    │
    └─ 交给主模型（最多 5 步）
          │
          ├─ 已经有业务卡片 → 返回这张卡片
          │
          └─ 只有文字
                ├─ 心愿备用金的用途、金额、用钱日都齐了 → 补确认卡
                ├─ 转账卡号和金额都齐了 → 补转账确认卡
                ├─ 客户要看的内容没有卡片 → 补查账单、银行卡、订阅、安全中心、理财或心愿列表
                └─ 文字说已经办成，但没有确认卡 → 改成「这一步还没有执行」
```

主模型是通义千问 `Qwen/Qwen3.5-122B-A10B`，走魔搭接口，关闭长思考，工具由模型自己选。文字检查优先用 `Qwen/Qwen3.5-35B-A3B`，失败再用主模型。两个都调不通时，保留主模型原文。

文字检查只能补「查看」类卡片。转账、申购、存入、取回、冻结、退订的确认单，不由检查模型生成。

客户在聊买衣服、买礼物时，这一轮不出理财货架、产品详情、配置建议和申购，并说明不做商品导购。客户要把钱单独留到某一天，再办心愿备用金。

密码确认走单独接口。成功后把回执写入会话，并返回最新余额，小程序据此刷新顶部余额。

## 6. 组成与数据

| 部分 | 说明 |
| --- | --- |
| 微信小程序 | 登录、对话、业务卡片、确认和密码、适老版、语音 |
| 服务程序 | Python / FastAPI，地址 `http://127.0.0.1:8001` |
| 账本 | 本机 SQLite。客户、卡、流水、理财、订阅、心愿备用金、预警都在这里 |
| 会话 | 最近对话在服务进程内存里。重启后对话清空，账本还在 |

登录后，每次对话和确认都校验令牌。令牌绑在该客户身上，退出后失效。

## 8. 演示环境

需要 Windows、Python 3.10 及以上、微信开发者工具。模型令牌放在环境变量 `MODELSCOPE_TOKEN`，不要写进文档或代码仓库。

```powershell
cd "Bank agent"
python -m pip install -r requirements.txt
$env:MODELSCOPE_TOKEN = "魔搭推理令牌"
python init_db.py
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8001
```

再用微信开发者工具打开 `BankingMiniprogram`。本地设置里关闭合法域名校验，否则访问不了 `http://127.0.0.1:8001`。仓库里的本地配置已经关掉这项校验。先启动服务，再编译小程序。接口页：`http://127.0.0.1:8001/docs`。

语音优先用微软晓晓，本机要能访问语音服务。这一次访问失败时，改用 Windows 系统语音。语速分别用 `TTS_EDGE_RATE` 和 `TTS_RATE` 调整。

## 9. 系统边界

- 账本、限额、流水都在本机数据库，用来把规则跑通。
- 跨行转账只扣付款人并记流水。
- 亲情预警把通知原文记入预警表，并显示在确认单上。
- 心愿备用金的计息、工作日和到点赎回在本服务里完成。产品和收益率是演示数据。
- 重启服务会清空当前对话和还没入账的确认卡。已经确认的转账、申购、心愿备用金留在数据库里。
- 模型走外部推理接口。正式使用时，可以把同一套功能和规则接到行内模型。
